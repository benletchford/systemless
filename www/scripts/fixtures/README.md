# Browser performance checkpoints

`verify-runtime-pacing-cdp.mjs` accepts `SYSTEMLESS_RUNTIME_SETUP_ACTIONS_PATH` and `SYSTEMLESS_RUNTIME_CHECKPOINT_PATH`. A checkpoint splits setup from measurement, captures the page at the starting tick, and rejects a run unless its screenshot size, optional instruction range, and color counts match. Set `checkEnd` to check the color counts again after measurement, and `cpuMhz` to require one guest clock throughout the sample. The report includes the accepted checkpoint and frame-time metrics. Optional screenshot paths are `SYSTEMLESS_RUNTIME_CHECKPOINT_SCREENSHOT_PATH` and `SYSTEMLESS_RUNTIME_CHECKPOINT_END_SCREENSHOT_PATH`.

`ev-nova-flight-actions.json` enters PPC flight and holds thrust using guest-tick waits. `ev-nova-flight-checkpoint.json` screens for the flight workload observed at a 756×469 headless viewport. The pixel assertion counts yellow ship pixels near screen center; the instruction range rejects materially different launch paths. A rejected run must not be used in a performance comparison. Accepted screenshots are a workload check, not a full emulation save state or proof of identical guest execution. Compare paired runs at the same guest clock and inspect their accepted instruction counts before attributing a small timing difference to code.
