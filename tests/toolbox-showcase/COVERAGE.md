# Toolbox Showcase coverage

The committed fat archive is exercised by four Systemless profiles (68K and PPC, each with the Systemless theme and Classic System 7), a 59-checkpoint native overview on both BasiliskII and SheepShaver, and six focused native scenarios. This report covers the fixture’s 16 pages and its specified interactions; it does not assert general compatibility with every Toolbox routine or operating-system configuration.

The current native evidence contains 210 scenario-bound screenshots and three PCM reference files, each proven on both emulators. The Systemless integration sequence has 58 framebuffer checkpoints plus semantic assertions. Native runs use Mac OS 8.1 at 800 × 600, with an indexed 8-bit BasiliskII display and a direct-color 32-bit SheepShaver display. Both native first-visit sprite scenes now pass their pixel/region checks and match Reset.

## What is compared

* **Systemless:** exact per-profile frame references, with the existing narrowly scoped event timing masks, plus window/menu/control state, TextEdit contents and scrap, list data, drawing pixels, file/resource state, event/cursor state and sound commands. The sprite reset comparison includes the actual masked raster and validation readouts.
* **Native overview:** 85 reviewed image regions per emulator and 12 independent before/after relationships. They cover restored defaults, modal checkbox mutation, device-appropriate palette animation, resource release/reload, first/reset sprite equality and exact 24-pixel raster translation. SysBeep must emit at least 256 non-silent frames within its isolated capture interval and return to silence. The manifest records the precise regions and exclusions, including the known last pointer position for each checkpoint and blinking insertion carets.
* **Native 3D:** visible PPC geometry, clear color, silhouette overlap of at least 85%, and at least 400 interior pixels within eight RGB levels of SheepShaver. The 68K slice deliberately uses its labelled QuickDraw fallback.
* **Native sampled audio:** both emulators produce identical full/75%/50% resource waveforms. Systemless is compared at 22,050 Hz against every second native 44,100 Hz sample: duration within one sample, maximum error three 8-bit levels and mean error at most one. No phase, gain or frequency fitting is applied. Flush, Quiet, callback completion and disposal have separate outcome checks.

Native fonts, chrome, device-depth quantization and the configured SysBeep alert may differ from Systemless. Native palette animation is unavailable on direct-color devices. Event timestamps, accumulated counters and virtual key codes depend on the input/timing path; the behavioral checks retain event kinds, held-state and modifier results, queue outcomes and cursor visibility. Focused scenarios start from fresh launches, so unrelated menu checkmarks can differ from the cumulative overview.

## Reproduce and verify

Build and verify the fat archive with `./tests/toolbox-showcase/build.sh --verify`. Run `cargo test --locked --test toolbox_showcase`, then repeat with `SYSTEMLESS_PREFER_POWERPC=1`. Both use the Systemless theme by default. Repeat both architecture runs with `SYSTEMLESS_TOOLBOX_THEME=classic-system7` for the classic baselines. Do not set the reference-update environment variable during verification.

Replay `oracle/overview.json` and the six focused JSON scenarios against the same archive in both native emulators. The scripts use mouse/key input, tick delays, screenshots, and (for resource audio) displayed-state pixel gates. The audio-capable runner records raw 44,100 Hz signed 16-bit big-endian stereo plus per-checkpoint written-frame positions. Emulator ROMs, system software and machine-specific setup remain outside this repository.

Run `python3 tests/toolbox-showcase/oracle/verify_coverage.py` to validate the page inventory and published identities; CI performs this check. Run `python3 tests/toolbox-showcase/oracle/verify_overview.py <overview-capture-directory>` to compare a fresh native overview, including PCM. Pillow is required for the latter. Its input directory contains the two emulator output folders and their capture reports; it writes `overview-verification.json` with the actual comparison results.

The `*-capture.json` files bind each native scenario to the archive, emulator image/source revision and published evidence. `overview-capture.json` also records the precise region checks and state relationships. Capture identities prove which artifacts belong together; the outcome verifiers and reviewed native states establish what the application actually did. Refreshing references requires reviewing changed outcomes, never merely accepting successful process exits.
